# Project Instructions

## General
- Always preserve the existing project structure.
- Explain significant changes before making them.
- Prefer minimal changes over complete rewrites.
- Do not delete files unless explicitly requested.
- Use 4 spaces for indentation in all files.

## HTML
- Write semantic HTML5.
- Use accessible elements and ARIA attributes when appropriate.
- Use kebab-case for class names and IDs.

## CSS
- Use plain CSS unless the project already uses a framework.
- Follow desktop-first responsive design.
- Prefer Flexbox and CSS Grid.
- Group related styles together.
- Keep class names clear and descriptive.
- Keep selectors as simple as possible.
- Reuse existing classes before creating new ones.

## JavaScript
- Use modern ES6+ syntax.
- Prefer const over let; use var never.
- Write modular, reusable code.
- Use camelCase for variables, functions, object properties, and methods.
- Avoid global variables.
- Add comments only for complex logic.
- Handle errors gracefully.
- Avoid inline event handlers.
- Prefer event delegation when appropriate.

## Performance
- Minimize DOM manipulations.
- Optimize images and assets.

## Editing Rules
- Never rewrite an entire file if only a small change is needed.
- Preserve existing formatting.
- Preserve existing comments.
- Do not rename classes, IDs, variables, or files unless explicitly requested.
- Show only the modified code unless a full file is requested.

## Debugging
- When fixing bugs:
  - Explain the root cause.
  - Describe the fix.
  - Show only the necessary code changes.

## Communication
- Before writing code, briefly explain the approach.
- Ask for clarification if the requirements are ambiguous.
