# Legacy Test Map for the Vitest Migration

This inventory records the behavior of the tests currently registered in
`tests/tests.js`. The legacy runner registers 20 data tests and one UI test.
`tests/config.json` enables the data tests and disables the UI test. The runner
shuffles each group and runs its members concurrently. `TestConfig` converts
exceptions and mismatches to `success: false`; it does not throw a failing test
assertion. Its `ANY_VALID` marker only rejects `undefined`, `null`, and `NaN`.

Paths below are relative to `tests/`. "Local" means the test does not make a
live request; it does not imply that a Vitest local suite exists yet.

## Empty method test

`api/gitHubClient/createHttpError.test.js` is empty and is not imported by
`tests/api/index.js`. The method in `src/js/api/gitHubClient/gitHubHttpApi.js`
maps a response status to a user-facing error and returns developer details
containing status, optional API message, and URL. A malformed JSON body falls
back to the status message and logs a warning. Keep the empty file outside
Vitest discovery until subphase 2.4, where mocked response bodies can cover
those method behaviors.
